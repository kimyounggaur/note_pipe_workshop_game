# 음표 파이프 공방

붙임줄·이음줄·레가토를 악보와 물길, 소리, 밸브 조작으로 배우는 세로형 음악이론 게임이다. 설계서 v1.0(2026-11-14)의 JT0–JT9 계획과 부록 B·C를 바탕으로 구현한다.

현재 상태는 **구현 후보판**이다. 자동 검사와 실기기 검수를 구분하며, JT9와 정식 v1.0 완료를 선언하지 않는다. 최신 확인 범위와 미실행 항목은 [게이트 보고서](docs/joint-gate-report.md)를 따른다.

## 실행

배포 산출물은 CSS·SVG·JavaScript를 모두 포함하는 `index.html` 하나다. 외부 글꼴, 이미지, 라이브러리, 음원 서버를 사용하지 않는다. 오디오는 Web Audio로 합성한다. 파일을 브라우저에서 직접 열거나 정적 서버로 제공한다.

```sh
python -m http.server 8080
```

브라우저에서 `http://localhost:8080/index.html`을 연다. 주소 끝에 `#test`를 붙이면 자체 검사 결과를 볼 수 있다. 실제 소리는 사용자의 첫 터치나 클릭 뒤에 활성화된다.

## 배우는 순서

| 단 | 작업일 | 의뢰 수 | 처음 맞힘 통과 기준 | 배우는 것 |
|---|---|---:|---:|---|
| 0 | 물길 읽기 | 6 | 5 | 가로는 시간, 세로는 높이, 방울은 소리의 시작 |
| 1 | 붙이기 | 7 | 6 | 같은 높이의 두 음을 붙여 길이 더하기 |
| 2 | 붙임의 셈 | 8 | 7 | 점음표와 같은 길이, 마디선, 2½박 |
| 3 | 잇기 | 7 | 6 | 틈을 없애도 음마다 방울은 남음 |
| 4 | 곡선 읽기 | 7 | 6 | 같은 모양의 곡선을 음과 범위로 읽기 |
| 5 | 겹친 곡선 | 7 | 6 | 이음줄 안의 붙임줄 |
| 6 | 수리소 | 7 | 6 | 틀린 연결의 원인을 찾아 수리하기 |

의뢰 49건의 씨앗은 부록 B.9와 일치한다. 셈 14건, 말 3건, 설계도 22건, 소리 3건, 수리 7건이다. 정답, 곡선, 방울 수, 보기, 소리 길이, 누르는 구간은 씨앗에서 계산한다.

작업일은 정해진 순서로 진행한다. 처음 맞히면 ●, 고쳐 맞히면 ◐로 기록한다. ◐ 의뢰는 마감 앞에 한 번 더 나오지만 그날의 통과 비율을 바꾸지 않는다. 밸브 솜씨는 진행 조건에 포함하지 않는다.

## 조작

- 셈: 악보를 보고 방울 수나 가장 긴 소리를 고른 뒤 확정한다.
- 배관: 떼기·잇기·붙이기 도구를 고르고 이음매를 누른 뒤 검수한다.
- 붙이기: 같은 높이의 이웃한 음에만 적용된다. 뒤의 소리 시작을 없애고 길이를 더한다.
- 잇기: 틈을 없앤다. 음마다 소리 시작과 방울이 남는다.
- 밸브: 누르는 동안 물이 흐른다. 기계 밸브를 보고 연습하거나 건너뛰어 납품할 수 있다.
- 도면첩: 모은 카드 8장과 발견 장면 4개를 다시 본다.
- 자유 공방: 열린 작업일의 가락을 골라 빠르기 40–100에서 연결을 바꾼다. 기록과 작업일 통과에는 반영하지 않는다.

Tab으로 조작 대상을 옮기고 Enter 또는 Space로 버튼을 누른다. 밸브는 터치·마우스·키보드의 누르고 있기를 지원한다. 실제 기기에서의 터치 지연과 보조기술 완주는 별도 검수가 필요하다.

## 구현 구조

개발 중에는 파일을 나누고 배포 시 한 HTML로 합친다. `parts/`와 `tests/`는 개발 원본이며 배포 시 외부에서 불러오지 않는다.

| 파일 | 역할 |
|---|---|
| `parts/engine.js` | 분수, 음가, 곡선, 소리 구간, 검수, 셈, 밸브 판정과 이론 검사 |
| `parts/curriculum.js` | 49개 원본 씨앗, 작업일, 도면 카드, 발견 장면 |
| `parts/view.js` | 같은 `X(박)`을 쓰는 악보와 물길 SVG |
| `parts/audio.js` | 합성음, 오디오 클록 예약, 묶음 취소, 밸브 |
| `parts/storage.js` | SaveV1 검증, 백업, 인메모리 폴백 |
| `parts/app.js` | 상태와 전이, 의뢰 흐름, 기록, 화면 연결 |
| `parts/screens.js` | 타이틀·지도·마감·도면첩·설정·자유 공방 |
| `parts/style.css`, `parts/screens.css` | 화면 배치와 강철·놋쇠·물 색상 |
| `parts/shell.html` | 고정 작업 화면과 단계별 조작부 |
| `parts/audio-tests.js`, `parts/app-tests.js` | 오디오 스파이와 앱 전이 검사 |
| `tests/*.cjs` | Node에서 실행하는 독립 검사 |

길이는 분수로 계산하고 화면 좌표와 오디오 시각에서만 소수로 변환한다. 음표 길이 정답표나 곡선의 이름을 씨앗에 저장하지 않는다. 곡선의 분류는 음과 범위에서 도출한다. 붙임줄과 이음줄은 악보에서 같은 선을 쓴다.

시운전의 음은 오디오 클록에 미리 예약한다. 음을 타이머로 하나씩 이어 붙이지 않는다. SVG 물·방울·물머리를 같은 재생 위치로 갱신한다. 화면 이동과 재생 중단 시 예약된 소리를 함께 취소한다.

## 저장

`localStorage`의 `ppg_save_v1`에 설정, 작업일 도장, 도면 카드, 본 발견 장면, 진행 중 의뢰를 저장한다. 저장 형식은 `version: 1`이다. 빠진 선택 필드는 기본값으로 채운다.

손상되거나 더 높은 버전인 기록은 원본을 `ppg_save_v1_backup`에 남기고 기본값으로 시작한다. 저장소 사용이 막히면 현재 방문 동안 메모리로 동작하며 설정 화면에 저장 불가를 표시한다. 소리 재생 중에는 기록을 저장하지 않고 납품 시 저장한다.

기록 초기화는 설정 화면의 확인 절차를 거친다. 기기나 브라우저가 바뀌면 로컬 기록이 공유되지 않는다.

## 자동 검사

```sh
node tests/engine.cjs
node tests/audio.cjs
node tests/storage.cjs
node tests/app.cjs
node tests/journey.cjs
```

2026-11-18 현재 확인한 결과:

| 검사 | 결과 | 확인 범위 |
|---|---:|---|
| 이론·검수·셈·판정·출제 제약 | 44/44 | 유효 배치 8,400개와 서로 다른 배치의 쌍 257,820개 포함 |
| 부록 B.3 잠금 정답표 | 49/49 | 방울, 물줄기, 곡선, 가장 긴 소리, 울리는 길이, 누름 구간·횟수 |
| 오디오 스파이 | 9/9 | 예약과 취소 등 API 동작. 실제 소리 청취는 포함하지 않음 |
| 저장 | 4/4 | 왕복, 손상 백업, 폴백, 초기화 |
| 브라우저 자가검사 전체 | 68/68 | 실제 DOM·초점·그림 및 8개 크기에서 1,064장면 |
| 전체 진행 추가 검사 | 8/8 | 의뢰49개·발견4개·작업일7개·도면8장 |

설계서 TH-07의 거절 개수는 13,740개로 적혀 있으나, 같은 8,400개 유효 배치를 현재 검사에서 순회하면 18,408개의 높이가 다른 붙임 요청을 거절한다. 모든 요청에서 원본 배치 불변까지 확인했다. 이론 엔진을 바꾸지 않고 수치 차이를 보고서에 남겼다.

## 결정과 범위

D1–D13의 선택과 사유는 게이트 보고서에 기록한다. 이번 구현은 강철·놋쇠·물 색의 인라인 SVG와 시스템 글꼴을 사용한다. 제목은 『음표 파이프 공방』을 유지하며 캐릭터는 놋쇠 방울이다.

7단 이후의 악기별 레가토, 틈 조절, 쉼표·임시표·16분음표·교사 의뢰 카드는 후속 범위다. 현재 0–6단의 자연음 도–라, 최대 5음·6박, 2/4·3/4·4/4와 지정 음가에 집중한다.

## 배포와 남은 검수

새 GitHub 저장소 생성과 Vercel 정적 배포가 설계서 D10의 목표다. 2026-11-19 기존 빈 저장소 `kimyounggaur/note_pipe_workshop_game`을 확인하고 전체 소스를 main에 반영했다. CLI 인증 대신 연결된 GitHub API로 커밋과 브랜치 반영을 수행했다. Vercel의 새 프로젝트 생성은 자동 승인 검토에서 거절되어 배포하지 않았다. 외부 리소스 생성·비용 가능성에 대한 명시적 승인이 필요하다는 사유다. 실행 HTML과 전체 소스를 먼저 제공한다.

실제 iPhone·Android, 무선 이어폰, 사람의 손으로 하는 밸브, 같은 음의 이음과 붙임의 청취 구분, VoiceOver·TalkBack, 학습자·강사 검수는 `NOT_RUN`이다. 오디오 API 자동 검사 통과를 이 검수의 대체로 사용하지 않는다.

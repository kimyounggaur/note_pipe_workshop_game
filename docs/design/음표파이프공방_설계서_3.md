## 7. 학습 설계

### 7.1 사다리

한 단이 작업일 하나다. v1.0은 0~6단이다 [권장: 범위는 기획안과 같다. 2단의 이름만 바꿨다].

| 단 | 작업일 | 배우는 것 | 새로 생기는 것 | 의뢰 방식 | 버전 |
|---|---|---|---|---|---|
| 0 | 물길 읽기 | 가로는 시간, 세로는 높이. 음표 하나에 방울 하나. 곡선이 없으면 같은 음도 따로 낸다 | 시운전, 셈 | 셈 | v1.0 |
| 1 | 붙이기 | 같은 높이의 이웃한 두 토막을 붙이면 한 통이 된다. 방울은 하나, 길이는 합 | 떼기, 붙이기, 검수, 밸브 | 말, 셈, 설계도 | v1.0 |
| 2 | 붙임의 셈 | 높이가 다르면 붙지 않는다. 2박 + 1박 = 3박. 마디선을 넘는 소리, 음표 하나로 못 적는 길이 | 거절, 발견 장면 | 말, 설계도, 셈 | v1.0 |
| 3 | 잇기 | 이음쇠를 달면 틈이 사라지고 방울은 남는다. 뗌과 이음을 귀로 가린다 | 잇기, 소리 의뢰 | 말, 소리, 설계도, 셈 | v1.0 |
| 4 | 곡선 읽기 | 똑같이 생긴 곡선의 이름은 양 끝 음이 정한다. 같은 음이 낀 이음줄 | | 설계도, 셈 | v1.0 |
| 5 | 겹친 곡선 | 이음줄 안에 붙임줄이 있다. 곡선 둘을 따로 읽는다 | | 설계도, 셈, 소리 | v1.0 |
| 6 | 수리소 | 틀린 연주를 알아보고 고친다 | 수리 의뢰 | 수리 | v1.0 |
| 7 | 레가토 공방 | 악기마다 잇는 법이 다르다(숨, 활, 손가락, 울림) | 악기 카드, 음색 바꾸기 | | v1.1 |
| 8 | 틈의 크기 | 스타카토, 보통, 테누토, 레가토를 틈의 크기로 견준다 | 틈 조절 | | v1.2 |
| 9 | 넓히기 | 쉼표, 임시표와 붙임줄, 16분음표, 긴 가락, 교사 의뢰 카드 | | | v1.3 |

4단이 이 타이틀의 중심이다. 0~3단은 4단에서 "같은 곡선을 다르게 읽는" 순간을 위한 준비이고, 5~6단은 그 읽기를 겹친 곡선과 틀린 배관에 쓰는 연습이다.

### 7.2 작업일 규칙

[설계]

- 의뢰는 정해진 순서로 나온다. 다시 해도 순서가 같다.
- 발견 장면은 의뢰 사이에 끼고 채점하지 않는다.
- ◐로 끝난 의뢰는 마감 의뢰 앞에 한 번 더 나온다. 다시 나온 의뢰의 결과는 도면 카드에는 적지만 그날의 통과 계산에는 넣지 않는다.
- **통과**: 처음 나온 의뢰 가운데 ●가 80% 이상(올림). 6건이면 5, 7건이면 6, 8건이면 7이다. 밸브 결과는 넣지 않는다(R9).
- 통과하면 다음 작업일이 열린다. 통과한 작업일은 몇 번이든 다시 할 수 있다.
- HUD의 진행 점은 처음 나온 의뢰 수만큼이다. ●는 채운 점, ◐는 반 채운 점, 지금 의뢰는 테두리가 굵은 점이다 [검증: 점의 세 모양].
- 걸리는 시간은 작업일마다 1분 30초~4분으로 잡는다. 소리가 차지하는 시간은 계산값이다. ♩=60에서 납품 듣기의 합이 작업일마다 21~29초, 밸브를 전부 하면 27~42초다 [계산]. 여기에 셈 의뢰 하나에 약 10초, 배관 의뢰 하나에 약 15~20초의 판단 시간을 더한 어림이고 재지 않았다. 납품 듣기와 밸브는 건너뛸 수 있다.

### 7.3 v1.0의 의뢰 목록

의뢰 49건이다. 씨앗은 부록 B.9, 엔진이 계산한 정답표(이음매, 방울, 소리, 곡선, 누르는 구간)는 부록 B.3이다 [계산]. 모든 의뢰가 5.5절의 출제 제약을 지킨다. 아래는 의뢰마다 무엇을 겪게 하려는지다. 음표는 따로 적지 않으면 4분음표다. ⌒는 붙임줄, /는 마디선이다. 이음줄은 기호 없이 "이음줄"이나 "곡선"이라고 말로 적었다.

### 7.4 발견 장면

[설계] 초안의 비교 화면이다. 새 배치를 만들지 않는다. 작업 화면의 무대에 두 물길 "가"와 "나"를 번갈아 놓는다. 조작부 윗줄에 [가] [나], 아랫줄에 [물 틀기]와 [알겠어요]를 둔다. 같은 자리에서 바뀌므로 달라지는 곳만 눈에 띈다. 채점하지 않고, 도면첩에서 다시 볼 수 있다. 두 물길의 값은 엔진으로 계산했다 [계산].

| 장면 | 자리 | 가 | 나 | 문장 |
|---|---|---|---|---|
| S1 | 2단, d2-02 뒤 | 3/4 도(2분)⌒도. 방울 1, 도 3박 | 3/4 도(점2분). 방울 1, 도 3박 | 소리가 같아요. 2박 + 1박 = 3박. 점2분음표 하나로도 적을 수 있어요. |
| S2 | 3단을 시작할 때 | 3/4 도 레 미, 모두 뗌. 방울 3 | 같은 가락, 모두 이음. 방울 3 | 음도 방울 수도 같아요. 틈만 달라요. 틈이 없으면 이어서 들려요. |
| S3 | 4단, d4-02 뒤 | 2/4 도⌒도. 방울 1, 도 2박 | 2/4 도–레 곡선. 방울 2, 도 1박 → 레 1박 | 곡선은 똑같이 생겼어요. 이름은 양 끝의 음이 정해요. |
| S4 | 4단, d4-03 뒤 | 4/4 미⌒미 솔(2분), 전체에 이음줄(곡선 둘). 방울 2, 미 2박 → 솔 2박 | 같은 음표에 곡선 하나. 방울 3, 미 1박 → 미 1박 → 솔 2박 | 방울이 2번, 3번이에요. 두 미 사이에 따로 곡선이 있는지 보세요. |

S4는 5단의 겹친 곡선을 미리 보여 주는 장면이다. S1의 문장은 기획안의 "점은 붙임줄을 줄여 적은 거예요"를 고친 것이다. 점음표가 붙임줄의 줄임은 아니므로 길이가 같다는 것만 말한다.

### 7.5 기록, 통과, 보상

| 기록 | 내용 |
|---|---|
| 물길 | 의뢰마다 ●(셈이나 검수를 한 번에 맞힘) 또는 ◐ |
| 밸브 솜씨 | 의뢰마다 매끈, 한 곳 샘, 여러 곳 샘, 기계, –(건너뜀). 그 의뢰에서 낸 가장 좋은 것 |
| 도장 | 작업일을 통과하면 한 개 |
| 매끈 도장 | 그날 밸브가 있는 의뢰 전부를 손으로 매끈하게 낸 날 |
| 도면 카드 | 8장. 익힌 연결 하나에 한 장 |

도면 카드는 엔진의 꼬리표(`tagsOf`)로 정한다. 그 꼬리표가 붙은 의뢰를 처음 ●로 납품할 때 얻는다 [계산: 처음 얻는 의뢰].

| 카드 | 꼬리표 | 처음 얻는 의뢰 | 카드의 한 줄 [설계] |
|---|---|---|---|
| 따로 내기 | `plain` | d0-01 | 곡선이 없으면 음표마다 새로 시작해요. 같은 음도 따로 내요. |
| 붙임줄 | `tie` | d1-01 | 같은 높이의 이웃한 두 음만 잇는 곡선이에요. 뒤의 음은 다시 내지 않고 길이를 더해요. |
| 점음표와 같은 길이 | `tie-dot` | d2-02 | 2박 + 1박 = 3박. 점2분음표 하나와 길이가 같아요. |
| 마디선을 넘는 붙임줄 | `tie-bar` | d2-05 | 마디선을 넘는 소리는 붙임줄로 적어요. |
| 붙임줄로만 적는 길이 | `tie-need` | d2-07 | 2½박은 음표 하나로 적을 수 없어요. 붙임줄로 적어요. |
| 이음줄 | `slur` | d3-01 | 음들을 틈 없이 이어요. 음마다 새로 시작해요. 이렇게 잇는 연주를 레가토라고 해요. |
| 같은 음이 낀 이음줄 | `slur-same` | d4-03 | 곡선이 다른 음까지 덮으면 이음줄이에요. 그 안의 같은 음은 다시 내요. |
| 이음줄 안의 붙임줄 | `tie-in-slur` | d5-01 | 곡선이 둘이에요. 안쪽은 붙임줄, 바깥쪽은 이음줄이에요. |

- 카드에는 악보, 물길 그림, 방울 수, 소리 재생 단추, 한 줄 설명, 밸브 솜씨의 최고 기록이 있다. 모으면 요약 노트가 된다.
- 카드의 뒷면에 "관은 비유예요. 곡선의 이름은 양 끝 음이 정해요."를 적는다(3.4절).
- 6단에는 새 카드가 없고 도장만 있다.
- 마감 화면은 그날의 것만 보여 준다. ● 수, 도장, 새 카드, 의뢰별 기록. 점수, 재화, 상점, 순위표는 없다.

### 7.6 자유 공방

[설계] 별첨 1의 화면을 작업 화면의 틀 안에 넣는다. 열어 둔 작업일의 가락 가운데 하나를 골라 이음매를 마음대로 바꾸고, 시운전하고, 밸브를 눌러 본다. 설계도의 곡선이 내 이음매를 따라 바뀐다. 빠르기는 40~100에서 고른다. 판정은 보여 주되 기록하지 않는다. 같은 높이의 두 음만 이음으로 이으면 "이 곡선은 악보에서 붙임줄로 읽혀요"를 알려 준다. 수업에서 화면을 띄워 설명하는 용도를 겸한다(D3).

### 7.7 튜토리얼

[설계] 글로 된 안내 창을 쓰지 않는다. 의뢰 안에서 한 번씩 손으로 해 보게 한다.

| 때 | 하는 일 | 배우는 것 |
|---|---|---|
| 0단을 시작할 때 | 음 하나를 듣고 "들려요 / 안 들려요"를 고른다 | 소리 확인(6.5절) |
| d0-01 | [물 틀기]를 가리킨다. 물이 지나가며 방울이 켜진다 | 방울은 소리의 시작이다 |
| d1-01의 배관 | 붙이기를 가리키고, 고르면 이음매 칩을 가리킨다 | 도구를 고르고 이음매를 누른다 |
| d1-01의 밸브 | 기계 밸브를 한 번 보여 준 뒤 따라 하게 한다 | 누르고 있는 동안 물이 흐른다 |
| d3-01의 배관 | 잇기를 가리킨다 | 새 도구 |

가리킬 때는 그 단추에 테두리를 두르고 판독 줄에 한 문장을 적는다. 다른 단추를 막지 않는다.

### 8.4 연출 시간표

| 소리 없이 | 6.5절 |
| 동작 줄이기 | 기기 설정과 게임 설정을 모두 따른다. 8.4절의 연출을 0ms로 |
| 글자 확대 | 브라우저 글자 확대 130%에서 판독 줄 3줄, 의뢰 카드 3줄까지 넘치지 않아야 한다. 줄 높이를 고정했으므로 이때는 판독 줄과 의뢰 카드의 고정 높이를 함께 키운다 [설계] |
| 누르고 있기가 어려운 학습자 | 기계 밸브, 느리게. 밸브는 통과와 무관하다(R9) |

## 9. 기술 설계

### 9.1 구조

한 파일 `index.html`이다. 안에서 구획을 나누고 구획 머리에 주석을 단다. 스파이크가 이 순서다.

```
<style>     토큰 → 틀(5행) → HUD → 의뢰 카드 → 무대(설계도, 물길, 이음매) → 판독 줄 → 조작부 → 겹쳐 뜨는 화면
<body>      #app: hud, brief, stage(score, pipesWrap), readout, controls(단계별 묶음 넷) / settings, close, rotate
<script>
  1 THEORY   분수, 음표, 이음매, 소리, 곡선, 예약표                순수 함수(부록 C.1)
  2 JUDGE    검수와 원인 순서, 셈, 밸브 판정, 말 의뢰, 꼬리표       순수 함수(부록 C.1, C.2)
  3 JOBS     의뢰 씨앗, 작업일, 발견 장면, 문구                   부록 B.9, C.3
  4 STATE    상태와 setState, 전이 함수                         부록 C.4
  5 VIEW     치수, 설계도, 물길, render                         부록 C.5, C.6
  6 AUDIO    컨텍스트, 음색, 예약과 취소                         부록 C.7
  7 RUN      재생 다섯 가지, 프레임, 밸브, 끝내기, 중단, 입력      부록 C.8
  8 STORAGE  저장과 불러오기, 폴백
  9 SCREENS  타이틀, 지도, 마감, 도면첩, 자유 공방, 설정
  10 TESTS   검사 러너
  11 BOOT    입력 연결, 측정, 시작
```

의존 방향은 1~2 ← 3~4 ← 5~7 ← 9다. 1~2는 `window`와 `document`를 만지지 않는다.

### 9.2 상태 기계

```ts
type Screen = "title" | "map" | "work" | "close" | "book" | "free" | "settings";
type Phase  = "scene" | "count" | "pipe" | "valve" | "deliver";
type Sub    = "ready" | "countin" | "run" | "result" | "listen";

type State = {
  screen: Screen; day: string; idx: number; phase: Phase; sub: Sub;
  tool: Joint;                 // 고른 도구
  joints: Joint[];             // 내 이음매
  tries: number;               // 이 의뢰에서 틀린 횟수(0, 1, 2)
  assisted: boolean;           // 이 의뢰에서 한 번이라도 틀렸는가
  bad: number[];               // 검수에서 표시한 이음매
  dead: string[];              // 셈에서 꺼 둔 보기
  picked: string | null;       // 셈에서 고른 보기
  label: string;               // 준비 박 숫자
  msg: { tone: "" | "good" | "warn" | "bad"; text: string };
  valve: string;               // 이 의뢰의 가장 좋은 밸브 솜씨
  marks: null | { k: number; ok: boolean }[];   // 밸브 결과의 이음매 표시
  hearing: boolean;            // 의뢰 듣기 중
  results: { recipe: "full" | "half"; valve: string }[];
  retry: number[];             // 마감 앞에 다시 낼 의뢰의 순번
  sheet: "" | "settings" | "close";
  lowOk: boolean;              // 낮은 화면에서 "그래도 계속하기"를 눌렀는가
  // 설정: slow, …
};
```

- 상태는 `setState(patch)` 한 곳에서만 바뀐다. 전이 함수(`startJob`, `pick`, `confirmCount`, `applyTool`, `inspectNow`, `toDeliver`, `nextJob`, `abortRun`, `stopAndIdle`)가 다음 상태를 계산해 `setState`를 부른다 [검증: 스파이크에 `retry`와 `screen`을 뺀 나머지가 있다].
- 허용하는 전이는 4.8절의 그림이다.
- 재생(`run`)은 상태 밖의 객체다. 종류, 예약 시각, 누른 구간, 물 그림의 진행을 가진다. 프레임 함수는 준비 박 숫자나 단계가 바뀔 때만 `setState`를 부른다.
- 타이머(`setTimeout`)로 상태를 바꾸지 않는다. 시간에 따른 변화는 프레임 함수가 소리 시계를 읽어 만든다. 예외는 화면 크기 변화의 디바운스뿐이다 [검증: 소스].

### 9.3 뷰

- 틀은 HTML에 한 번 적는다. 조작부의 단계별 묶음 넷(셈, 배관, 밸브, 납품)도 전부 미리 두고 `hidden`으로 바꾼다(R13).
- 설계도와 물길은 "무엇을 그릴지"를 열쇠 글자열로 만들고, 열쇠가 바뀔 때만 다시 만든다 [검증]. 설계도의 열쇠는 의뢰, 곡선을 보이는가, 무대 폭. 물길의 열쇠는 의뢰, 이음매, 방울을 숨기는가, 무대 폭, 줄 간격이다. 재생 동안에는 열쇠가 변하지 않는다. 물, 켜진 방울, 물머리는 그 위에 속성만 바꾼다.
- 물길을 다시 만들 때 초점이 이음매에 있었으면 같은 번호의 이음매에 돌려준다 [검증].
- 무대의 치수는 위쪽 줄(HUD, 의뢰 카드)을 다 고친 뒤에 잰다(2.4절 1번).
- 가로 자리는 전부 `X(박)`에서 낸다. px를 누적하지 않는다.
- 화면 크기가 바뀌면 다시 그린다. 재생 중이면 무대 폭이나 줄 간격이 달라졌을 때, 또는 낮은 화면 안내가 떠야 할 때만 재생을 멈추고 다시 그린다 [검증].
- 가린 물길과 꺼 둔 방울은 지우지 않고 보이지 않게만 한다. 자리가 움직이지 않는다 [검증].

### 9.4 저장

```ts
type SaveV1 = {
  version: 1;
  settings: { volume: number; muted: boolean; slow: boolean; holdOffsetMs: number;
              motion: "system" | "reduced" | "full"; tutorialSeen: boolean; soundChecked: boolean };
  days: Record<string, { passed: boolean; stamp: 0 | 1 | 2; runs: number; best: number }>;   // 키 "d0"… stamp 1 도장, 2 매끈 도장. best: ● 수의 최고
  cards: Record<string, { got: boolean; valve: 0 | 1 | 2 | 3 }>;   // 키는 꼬리표("tie-bar"). valve 1 여러 곳 샘, 2 한 곳 샘, 3 매끈
  scenes: string[];                                                // 본 발견 장면("S1"…)
  stats: { jobs: number; clean: number; valves: number; smooth: number };
  active: null | { day: string; index: number; retry: number[];
                   results: { recipe: 1 | 2; valve: 0 | 1 | 2 | 3 | 4 }[] };   // recipe 1 ◐, 2 ●. valve 0 –, 1~3 위와 같음, 4 기계
};
```

- 키는 `ppg_save_v1`이다. `version: 1`을 지킨다. 필드를 더할 때는 없는 필드를 기본값으로 채우고 버전을 올리지 않는다.
- 손상되었거나 더 높은 버전의 저장을 만나면 기본값으로 시작하되 원본 문자열을 `ppg_save_v1_backup`에 남긴다.
- `localStorage`를 쓸 수 없으면 메모리에만 둔다. 이때 설정 화면에 "이 기기에서는 기록이 저장되지 않아요"를 보여 준다.
- 납품할 때마다 저장한다. 재생 도중에는 저장하지 않는다. `lowOk`는 저장하지 않는다(그 방문에서만 듣는다).

### 9.5 검사 러너

- `index.html#test`로 열면 작업 화면 대신 검사 결과표를 그린다. 묶음(TH, IN, CN, JD, GN, AU, ST, SV, CT)마다 통과 수와 실패한 검사의 이름을 보여 준다.
- 평소에는 불러올 때 한 번 돌리고 설정 화면에 "자가검사 68/68"만 적는다 [검증: 스파이크는 25/25]. `window.__tests`로 결과를 내어 준다.
- 소리 검사(AU)는 오실레이터 생성을 가로채 기록하는 방식으로 한다(부록 C.9). 실제 소리를 내지 않는다.
- 주소 끝의 `#이름`만 쓴다. 아티팩트 환경에서는 물음표 뒤의 값이 전달되지 않는다.

### 9.6 성능 예산

| 지표 | 예산 [설계] | 스파이크 [검증] |

### 9.7 오류 처리

- 전역 오류를 삼키지 않는다. 배포본에서는 한 번 기록하고 "문제가 생겼어요"와 새로고침 단추를 보여 준다.
- 예상되는 실패만 그 자리에서 처리한다. 오디오 생성·재개 거부(화면 시계로 이어 간다), 저장 용량 초과(메모리에 둔다), 소리 정지와 화면 가림(중단하고 알린다), 낮은 화면(안내하고 계속할 수 있게 한다).
